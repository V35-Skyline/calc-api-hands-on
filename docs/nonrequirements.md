# 非機能要件

このドキュメントは、PoC向けの非機能要件を定義します。運用レベルの要件は別途検討すること。

## デプロイと環境
- デプロイ先リージョン: Azure 東日本（Japan East）
- 実行プラン: Azure Functions の Consumption Plan を想定
- デプロイ: PoCのため本番デプロイや自動化は不要（手動デプロイ／ローカル実行で十分）
- OS/ランタイム: Python 3.11 を利用すること（Azure Functionsにおける3.11サポートを事前に確認すること）

## パフォーマンスとスケーラビリティ
- 応答時間: PoCのため厳密なSLAは設定しない。一般的な計算リクエストは短時間で応答する想定。
- スケーリング: Consumption Plan の自動スケールに依存する。高負荷時の詳細設計は不要。

## セキュリティと通信
- 認証: PoCのため不要（公開エンドポイントとして扱う）
- 通信: HTTPS を使用すること（Azure側のデフォルトで確保）
- 機密情報: 接続文字列やシークレットは `local.settings.json` やAzureのアプリ設定に保持し、ソースコードへ直書きしないこと

## 監視と運用
- ロギング: 簡易なログ出力を実装し、必要に応じて Application Insights 等の導入を検討する
- 障害対応: PoCのため詳細なアラートは不要。重大な問題は手動で対処する

## 開発・テスト
- 依存管理: `requirements.txt` に依存を記載して再現性を担保する
- テスト: 単体テストを用意する（`tests` フォルダ）。E2Eや負荷試験は不要
- ローカル実行: Azure Functions Core Tools を使ったローカル実行は任意

## 制約・除外項目
- 本ドキュメントで扱わない項目: 高可用性、レート制限、WAF、CI/CD の自動デプロイ、カスタムドメイン設定
